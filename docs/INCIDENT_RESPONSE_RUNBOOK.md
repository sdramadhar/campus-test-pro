# Incident Response Runbook

Runbooks are required for:

- leaked secret
- database compromise
- account takeover
- unauthorized report access
- proctoring evidence exposure
- code-runner escape suspicion
- DDoS
- malware upload
- failed exam submission incident
- widespread outage

Default actions: contain, preserve logs, rotate secrets if needed, notify stakeholders, collect evidence, restore service, document timeline, and add preventive work.
